# v0.15.0 — Portable Assurance Lifecycle Evidence

TIS v0.15.0 adds the minimum portable contract required for assurance validity under change without transferring semantic or component-local judgment authority.

## Added

- `assurance/assurance-lifecycle-event.schema.json` for change detection, reassessment, invalidation, supersession, provenance, and authority evidence.
- Machine-verifiable representation of `non_material`, `material`, and `unknown` impact.
- Lifecycle dispositions for `current`, `stale`, `reassessment_required`, `invalid`, `superseded`, and `indeterminate`.
- Bounded reassessment scope and explicit supersession lineage.
- Negative validation proving that material or unknown impact cannot silently preserve current assurance.

## Cross-repository consumption evidence

The release decision is evidence-driven. The contract has been exercised through the TRQP Stack 2026.2 lifecycle path:

1. TRQP-TSPP owns the security/privacy posture materiality judgment and emits portable lifecycle evidence (`e952641fe28dd03b8015ed0ce22da053d9160a4a`).
2. trqp-conformance-suite consumes the lifecycle event and owns the bounded-versus-full conformance reassessment consequence (`da3d1f7b49625c774a17188e0d61f2101dcb1ba5`).
3. trqp-assurance-hub consumes both layers and owns current combined-assurance validity and recomposition (`ed501d460fe8a2b093ccfbcc931558b6888d7fe2`).

This demonstrates portable consumption without moving TSPP materiality semantics, CTS conformance semantics, or Hub recomposition semantics into TIS.

## Authority boundary

TSMM remains authoritative for canonical semantics. TIS owns serialization and validation of the portable evidence contract. Component repositories remain authoritative for their local judgments. The lifecycle schema explicitly declares `authorityTransfer: false` in its TSMM semantic binding.

## Fail-safe rule

Unknown impact is representable and must not collapse to reusable/current assurance. Consumers are expected to escalate toward reassessment, invalidation, or an indeterminate state according to their own authority.

## Compatibility

The change is additive. Existing v0.14.x artifacts remain valid unless a consumer explicitly adopts lifecycle handling. Unknown future versions remain unsupported until reviewed.

## Validation

```bash
npm run candidate:check
```

The candidate gate validates schemas, governance, repository relationships, TSMM alignment, TSMS compatibility, assurance lifecycle invariants, version consistency, documentation, Pages information architecture, Mermaid content, and candidate evidence generation.

## Residual uncertainty

This release proves portable lifecycle evidence and real cross-repository consumption. It does not by itself certify TRQP Stack 2026.2 or prove completed reassessment supersession; those are coordinated Stack release gates owned by the Assurance Hub programme.
