# Support

Use GitHub Issues for reproducible schema-validation defects, compatibility questions, documentation gaps, and adoption problems. Include the TIS version or commit, artifact/schema identifier, validation command, minimal input, observed result, and expected contract behavior.

For security-sensitive reports, follow [`SECURITY.md`](SECURITY.md) and do not publish exploit details in a support issue.

Support guidance does not create or override authority. TIS owns portable contract and validation semantics; upstream canonical meaning and downstream runtime/assurance decisions remain with their respective authoritative repositories.
